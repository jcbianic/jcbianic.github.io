FastAPI, in the Flask ecosystem.

Why

In 2021, I was working on a production Flask application when I discovered FastAPI. Type annotations on route parameters, automatic validation through Pydantic, OpenAPI documentation that writes itself. It clicked immediately.

Migrating to FastAPI didn't make sense for that project. The codebase existed, the dependencies were in place, and the churn would have been real for an uncertain gain. But the idea of annotating route handlers and letting the framework handle validation was too good to drop.

The question was obvious: can we have this on Flask?

How

Flask-Jeroboam is a Flask extension that brings the FastAPI developer experience to the framework. It reads type annotations on route functions, validates requests and serializes responses through Pydantic, and generates OpenAPI docs from function signatures.

The first implementation fit in ~100 lines wired into the application. Enough to validate the idea under real conditions. Late 2022, I decided to go all the way: extract it, structure it as a proper extension, write documentation, publish it.

The project stalled after that. On PyPI, but without a community to keep it alive. In February 2026, I picked it up again with a different intent. I wanted to ask a research question: can Claude contribute quality code to a project that already has five years of history, its own patterns, and decisions to respect? I'm still figuring that out.

What

  • Flask routes with type annotations and automatic Pydantic validation
  • Typed path, query, and body parameter parsing
  • Response validation and serialization against Pydantic models
  • OpenAPI documentation generated from function signatures
  • Consistent validation error handling with appropriate HTTP responses
  • Compatible with the existing Flask ecosystem — Blueprints, extensions, middleware

Install

pip install flask-jeroboam
